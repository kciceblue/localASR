# localASR — Design

A cross-platform (Linux + Windows) push-to-talk dictation tool written in Rust. While the user holds a configurable hotkey, audio is captured, transcribed in chunks via an OpenAI-compatible ASR endpoint, polished by a context-aware editor LLM, and pasted into whatever app currently has focus. A heavier on-release editor pass refines the final utterance using an optional domain-specific term database.

## Goals

- One executable, configured via TOML, with a separate GUI wizard subcommand for first-time setup.
- Works on X11, Wayland, and Windows without per-compositor special cases on Linux.
- Both model endpoints are user-replaceable as long as they speak the OpenAI HTTP shape (`/v1/audio/transcriptions`, `/v1/chat/completions`).
- Streaming feel: text appears within ~1s of pausing, not only after key release.
- Optional, user-curated **term database** lets the heavy editor disambiguate jargon, names, and homophones.

## Non-goals

- No GUI at runtime (no tray, no settings window). Wizard is for setup only.
- No focus-aware "only inject into text fields" check. We rely on the clipboard-paste contract: if the focused app doesn't accept paste, nothing happens.
- No local ASR or LLM inference. We always call out to a configured endpoint (which may itself be a local server like llama.cpp or whisper.cpp wrapped in an OpenAI shim).
- No macOS support in v1. Module boundaries keep the door open, but no code or testing.

## Decisions (locked)

| Topic | Decision |
|---|---|
| Language | Rust, single crate, single binary |
| API protocol | OpenAI-compatible for both ASR (`/v1/audio/transcriptions`) and editor (`/v1/chat/completions`) |
| Output mechanism | Clipboard-paste with save/restore (no character-by-character typing) |
| Streaming source | Chunked transcription, chunks delimited by VAD silence (default: silero-vad) |
| Editor passes | Two — light per-pause + heavy on key release |
| Linux input/output | `evdev` for hotkey capture, `uinput` for synthetic input. Works on X11 and Wayland uniformly. |
| Windows input/output | `RegisterHotKey` + `SendInput` |
| Runtime UI | None. Pure daemon + TOML. |
| Setup | `localasr setup` — egui-based wizard that writes config and runs end-to-end verification |
| Audio device | Default device unless overridden via wizard |
| Hotkey default | `RightCtrl` (configurable; also accepts chords). For chords, the session opens when **all** keys are down and closes the moment **any** key is released. |
| API key storage | Plain in TOML; supports `${ENV_VAR}` interpolation |
| First run with no config | Daemon errors with: "No config found. Run: `localasr setup`" |
| Term database | Optional via `[terms] enabled = true`. Strictly formatted `terms.toml`. Generated by `localasr extract <folder>` using the editor endpoint. Used by the **heavy editor only**. |
| Re-press during in-flight session | Abort current session immediately, start new utterance. Aborted in-flight HTTP calls are cancelled. |

## Subcommands

- `localasr` — run the daemon (default).
- `localasr setup` — launch GUI wizard.
- `localasr doctor` — non-interactive diagnostics: probe mic, both endpoints, hotkey capture, paste mechanism. Prints pass/fail per check and exits.
- `localasr extract <folder> [--out <path>]` — scan a folder, send chunked file contents to the editor endpoint with a glossary-extraction prompt, write strictly-formatted `terms.toml` (default path from config). File selection respects `.gitignore`. Files are chunked into ~8KB windows on line boundaries; chunks are processed sequentially (concurrency = 1 in v1 to avoid rate-limit complexity). Extracted entries from all chunks are merged, deduped by `name`, and sorted alphabetically before write.

```
    │   ├── asr_client.rs    # OpenAI /v1/audio/transcriptions client

    ├── wizard/
    │   ├── mod.rs           # egui app
    │   └── steps/           # one file per step (mic, asr, editor, hotkey, test, save)
    ├── extract/
    │   ├── mod.rs           # subcommand entrypoint
    │   └── scanner.rs       # file walking + chunking
    ├── terms/
    │   ├── mod.rs           # load/save terms.toml
    │   └── schema.rs        # strict serde types (name, aliases, hint)
    ├── config/
    │   ├── mod.rs           # paths, env interpolation, validation
    │   └── schema.rs        # strict serde types
    ├── platform/

    │   └── windows/         # RegisterHotKey + SendInput + OpenClipboard

```

**Why one crate, not a workspace:** wizard, daemon, and shared types share many of the same config / platform / terms structs. Single crate keeps types unified. Wizard GUI dependencies (egui ~7MB) end up in the daemon binary too — accepted in exchange for one-binary installation.

## Runtime model

- Tokio multi-thread runtime drives orchestration and HTTP.
- **Dedicated OS thread for audio** (cpal's callback is realtime; required).
- **Dedicated OS thread for hotkey** (evdev reads are blocking on Linux; Windows hook runs on its own pumped thread).
- Audio thread → pipeline: `crossbeam::channel` (lock-free, realtime-safe send).
- Hotkey thread → pipeline: `tokio::sync::mpsc` (small commands: `PressStart`, `Release`).
- All HTTP requests are tagged with a session ID; on session abort, in-flight `reqwest` futures are cancelled.

## Configuration

`~/.config/localasr/config.toml` (Linux, XDG) or `%APPDATA%\localasr\config.toml` (Windows).

```toml
[hotkey]
binding = "RightCtrl"          # single key or chord, e.g. "Ctrl+Alt+Space"

[audio]
device = ""                    # empty = system default; wizard fills with a device name
sample_rate = 16000

[vad]
backend = "silero"             # "silero" or "webrtc"
min_silence_ms = 400           # close chunk after this much silence
max_chunk_ms = 5000            # force-close chunk past this length

[asr]
base_url = "https://api.openai.com/v1"
api_key = "${OPENAI_API_KEY}"  # literal or ${ENV} interpolation
model = "whisper-1"
language = ""                  # empty = auto-detect
timeout_ms = 15000

[editor]
base_url = "https://api.openai.com/v1"
api_key = "${OPENAI_API_KEY}"
model = "gpt-4o-mini"
light_temperature = 0.0
heavy_temperature = 0.2
light_timeout_ms = 4000
heavy_timeout_ms = 15000

[editor.light]
enabled = true
context_chunks = 3             # last N chunks visible per light pass
system_prompt = ""             # empty = use built-in default

[editor.heavy]
enabled = true
system_prompt = ""             # empty = use built-in default

[terms]
enabled = false
path = "~/.config/localasr/terms.toml"

[injection]
mode = "clipboard_paste"       # only mode in v1
paste_shortcut = "Ctrl+V"      # platform default
restore_delay_ms = 100         # wait before restoring clipboard after paste
```

### `terms.toml` — strict schema

```toml
[[terms]]
name = "kubectl"
aliases = ["cube control", "cube cuttle"]
hint = "Kubernetes CLI tool"

[[terms]]
name = "tokio"
aliases = ["to kyo", "tokyo"]
hint = "Rust async runtime"
```

- `name` — required. The canonical spelling to use in output.
- `aliases` — required (may be empty). Common mis-hearings.
- `hint` — required (may be empty). Short disambiguation context.

Loader rejects any unknown keys and any entry missing `name`. Empty `aliases`/`hint` are allowed; they must be present as empty list / empty string.

## Data flow during one push-to-talk

```
[hotkey thread]    [audio thread]    [pipeline (tokio)]         [HTTP]
hotkey pressed ──► start capture ──► open utterance session
                       │
                       │ (16kHz mono PCM frames)
                       ▼
                  ring buffer ◄──── pulls frames ──► VAD
                                                      │
                            (silence ≥ min_silence_ms or chunk hits max_chunk_ms)
                            ────► emit chunk ─────────┼─► ASR POST ──► partial text
                                                      │                    │
                                                      │                    ▼
                                                      │              diff vs typed state
                                                      │                    │
                                                      │                    ▼
                                            light editor (last N chunks) ──► HTTP
                                                                              │
                                                                              ▼
                                                                       diff vs typed state
                                                                              │
                                                                              ▼
                                                            injector: backspace×N + paste new tail
                       ▲
hotkey released ◄──── stop capture, flush final chunk
                                                      │
                                                      ▼
                                heavy editor (full utterance + term DB if enabled) ──► HTTP
                                                                                          │
                                                                                          ▼
                                                                              injector: backspace×N + paste final
```

### Invariants

- **Typed-state tracker** (`daemon/state.rs`) holds the exact characters this utterance has written into the focused app. Every correction is `backspace × len(superseded_tail)` then `paste(new_tail)`. The injector never assumes the app's state matches — it only knows what *it* wrote.
- One utterance = one press–release. State resets between utterances.
- If hotkey is released before the light editor or ASR finishes a chunk, in-flight work completes, then the heavy editor runs over the unified text.
- If hotkey is re-pressed mid-correction, the current session aborts immediately (HTTP cancelled, no further injection), and a new utterance begins.

### Editor pass details

**Light pass (per VAD pause)**
- Triggered after each chunk transcribes.
- Input: last `context_chunks` chunks' text.
- Prompt: "Polish recent dictation. Fix obvious ASR errors only. Do not add or remove content. Reply with the corrected text for the last chunk and nothing else."
- Output replaces the most recent chunk's text in typed-state, which then gets diff-injected.

**Heavy pass (on release)**
- Triggered once when the hotkey is released and the final chunk completes.
- Input: full utterance text + (if `[terms].enabled`) the loaded term DB rendered into the system prompt.
- Term DB rendering: each `[[terms]]` entry becomes a line like `kubectl — Kubernetes CLI tool (sounds-like: "cube control", "cube cuttle")`. All terms are included; retrieval is not used in v1.
- Prompt: "Polish this dictation. Prefer the listed terms for any phrase that sounds like one of them. Preserve meaning and length."
- Output replaces the whole utterance via backspace + paste.

## Platform abstraction

```rust
trait Platform {
    fn hotkey_listener(&self, binding: &Hotkey) -> Box<dyn HotkeyStream>;
    fn read_clipboard(&self) -> Result<ClipboardSnapshot>;
    fn write_clipboard(&self, snap: ClipboardSnapshot) -> Result<()>;
    fn paste(&self) -> Result<()>;      // sends paste_shortcut
    fn backspace(&self, n: usize) -> Result<()>;
}
```

### Linux (`platform/linux/`)
- **Hotkey:** Open `/dev/input/event*` via `evdev` crate, filter for keyboard devices, listen for the configured key. Required: user in `input` group, OR a shipped udev rule installed during first run.
- **Input synthesis:** Create a `uinput` virtual keyboard via `uinput-rs`. Send key events for `paste_shortcut` and `Backspace`.
- **Clipboard:** Prefer `wl-clipboard-rs` if `$WAYLAND_DISPLAY` is set, else `x11-clipboard`. Both libraries exist as pure-Rust.

### Windows (`platform/windows/`)
- **Hotkey:** Always `SetWindowsHookExW(WH_KEYBOARD_LL)`. `RegisterHotKey` does not deliver hold-and-release events and does not support single-key bindings, so we use the low-level hook uniformly for both single keys and chords.
- **Input synthesis:** `SendInput` with `INPUT_KEYBOARD` events.
- **Clipboard:** `OpenClipboard`, `GetClipboardData`, `SetClipboardData`.

## Error handling

| Failure | Behavior |
|---|---|
| ASR endpoint unreachable or 5xx | Log error, skip that chunk's injection, keep capturing the rest of the utterance. |
| Light editor times out | Inject raw ASR text for that chunk. Continue. |
| Heavy editor times out | Leave the cumulative light-edited text in place. Log warning. |
| Clipboard race (user copies during session) | The save/restore cycle wins — anything the user copied mid-session is overwritten when we restore. Documented behavior. |
| Hotkey device disappears (USB unplug, etc.) | Log, retry acquisition every 2s. Daemon stays up. |
| VAD never fires (e.g., utterance is pure silence) | No chunks emitted, no injection, no error. |
| `terms.toml` missing while `[terms].enabled = true` | Daemon fails fast at startup with a clear error message. |
| `terms.toml` malformed | Strict-schema loader rejects with line/column. Daemon exits. |
| Wizard end-to-end test fails | Wizard refuses to save unless user explicitly overrides ("save anyway"). |

## Testing

### Unit tests
- VAD chunking edge cases (very short utterance, no silence, all silence, exactly `max_chunk_ms`).
- Diff-and-backspace state machine: every (old, new) → correct (backspace_count, new_tail).
- TOML schema round-trip (parse → serialize → equal).
- `${ENV}` interpolation: missing var, empty var, nested, escaped `\$`.
- `terms.toml` loader: valid, missing field, unknown field, malformed TOML.
- `localasr extract`: chunking deterministic; merging multiple LLM responses without duplicates.

### Integration tests
- Mock OpenAI-compatible server via `wiremock`. Drive a fake hotkey + canned 16kHz WAV through the pipeline. Assert the sequence of injector calls (saved clipboard, paste calls with expected payloads, backspace counts, restored clipboard).
- Failure-mode tests: ASR returns 500, editor times out, term DB missing, re-press mid-session.

### Platform / manual
- Per-platform checklist in `README`:
  - Wayland (GNOME) — hotkey + paste into Firefox, GNOME Terminal, VS Code.
  - Wayland (KDE) — same.
  - X11 — same.
  - Windows 11 — Notepad, browser, VS Code.
- `localasr doctor` should pass on all four before any release tag.

## Distribution

- `cargo build --release` produces one binary per platform target.
- Linux: tarball with binary + a sample `99-localasr.rules` udev file (read-only `/dev/uinput` for the `input` group). Installer documented in README; not automated in v1.
- Windows: zip with `.exe`. No installer in v1.

## Out of scope for v1 (deferred)

- macOS support.
- Local-only inference (no network).
- Tray icon / runtime UI.
- Multi-session history / undo across past utterances.
- Retrieval-based term DB (top-K embedding). All terms are dumped into the heavy prompt for now.
- Streaming / WebSocket ASR endpoints.
- OS keyring storage for API keys.
- Localization of wizard UI (English only in v1).
